Cómo trabajo

Infraestructura de confianza para sistemas de IA autónomos

Seguridad primeroModelado de amenazas desde el día 0. Seguridad basada en capacidades, zero-trust, mínimo privilegio por defecto.
Arquitectura hexagonalDominio puro con cero dependencias externas. Puertos y adaptadores para BD, HTTP, gRPC, OIDC.
Aislamiento por defectoAislamiento de tenants en la base de datos con RLS FORCE. Código no confiable en sandbox WASM con fuel medido.
Verificable por diseñoRecibos firmados y auditoría con hash encadenado. Cada acción del agente deja evidencia verificable.
Evaluar antes de confiarSpecs declarativos, oráculos de autorización y gates de regresión en CI. Comportamiento del agente probado, no supuesto.
Documentación vivaADRs para decisiones arquitectónicas. README como punto de entrada. Comentarios solo para el "porqué", nunca el "qué".
01Exploro primero: entiendo el código existente, las restricciones y los trade-offs antes de proponer
02Especifico explícitamente: ADR para decisiones irreversibles, spec para features
03Implemento en slices verticales: cada commit entrega valor verificable
04Verifico automáticamente: tests, linter, type-check y security scan en CI
05Reviso con criterio: revisión a fondo en riesgo medio/alto, revisión estructural en cambios de bajo riesgo
06Entrego por unidad de trabajo: tests, docs y código juntos, Conventional Commits
